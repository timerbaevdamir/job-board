# Линтинг

```bash
pnpm lint       # проверка
pnpm lint:fix   # с автоисправлением
```

`oxlint` (тот же движок, что у `oxfmt`, уже стоявшего в проекте). Форматирование — отдельно, `pnpm format`.

## Почему выключены четыре правила

Каждое выключение — сознательное, а не «чтобы не мешало».

**`react/react-in-jsx-scope`** — правило для классического JSX-трансформа. React 19 собирается с автоматической средой, `React` в области видимости не нужен.

**`import/no-unassigned-import`** — `src/main.tsx` импортирует `index.css` ради побочного эффекта. Это и есть предписанный способ подключить стили в Vite.

**`react/no-array-index-key`** — все шесть срабатываний приходятся на статические списки, которые никогда не переупорядочиваются и не фильтруются: абзацы описания вакансии, слои размытия, скелетоны-заглушки, звёзды рейтинга. Индекс там — стабильный идентификатор, а не источник багов. Правило имеет смысл для списков, которые меняются, но отличить одно от другого оно не умеет.

**`jsx-a11y/prefer-tag-over-role`** и **`jsx-a11y/no-noninteractive-element-to-interactive-role`** — оба срабатывают на корректной разметке кастомного комбобокса:

```tsx
<ul role="listbox">
  <li role="option" aria-selected>…</li>
</ul>
```

Это дословно паттерн из WAI-ARIA Authoring Practices, и `eslint-plugin-jsx-a11y` разрешает `ul → listbox` и `li → option` в настройках по умолчанию — oxlint эти умолчания пока не воспроизводит. Предлагаемая замена (`<select>` / `<option>`) для комбобокса с произвольной разметкой строк не подходит: нативный `<select>` не позволяет ни иконок, ни кнопки удаления из истории, ни группировки «Недавние / Рекомендуем».

Остальные правила `jsx-a11y` включены и **находят настоящие проблемы** — так была найдена карточка вакансии, которую нельзя было открыть с клавиатуры.
